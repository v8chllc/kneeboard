### Key context

Six structural findings now govern the normalized field mapping under open
decision 7:

1. The origin airport never appears in `navlog.fix`. Only the destination
   carries `type: "apt"`. Origin display must be synthesized from `.origin`.
2. TOC and TOD use `type: "ltlg"`, the same type as slot-eligible coordinate
   fixes. Computed points carry a descriptive `name` differing from `ident`
   (`TOC` / `TOP OF CLIMB`), while coordinate fixes have `ident == name` in
   canonical form (`52N050W` / `52N050W`).
3. `is_sid_star` is one flag covering both procedures. `via_airway` describes the
   leg *preceding* a fix, so it cannot be used alone — `BEALE` and `LBSTA` both
   carry a procedure name with `sid_star=0`. Separation requires both conditions.
4. There is no remaining-distance field. Per-fix `distance` is leg distance;
   remaining distance derives from `.general.route_distance`.
5. `is_sid_star` on TOC and TOD varies across OFPs. Three fixtures produced three
   patterns, so computed points must never be identified by that flag.
6. A VOR can sit inside a STAR (`BNN` on the EGLL arrival), so the STAR exclusion
   control and VOR handling interact.

### Decisions considered

- Chose WinGet over mise for `jq` because mise shims resolve per-directory and
  the Warp hooks run as bare `bash` subprocesses that may not have mise active.
- Reversed scenario 1 to KATL–KORD rather than switching to KDEN–KATL, keeping
  the originally documented airports while gaining a named SID.
- Dropped the proposed dedicated VOR-to-VOR scenario. Scenario 2 already supplies
  four interleaved VORs, so a separate fixture would add density without adding a
  behavior under test.
- Recommended an allowlist pattern for `ltlg` slot eligibility rather than
  blocklisting TOC and TOD, so unseen computed points such as ETPs or FIR markers
  fail safe into ineligibility.
- Kept the superseded KORD–KATL payload rather than deleting it, because SimBrief
  cannot re-serve an OFP once replaced.

Refined Kneeboard from a broad local preflight companion into a hosted,
simulation-only INS waypoint-entry tracker. Worked through product behavior one
question at a time, including LIDO navlog data, coordinate conversion, waypoint
eligibility, repeating slots 1–9, terminal Skip, cascading Pass, page
construction, persistence, authentication, security, hosting, and testing.

and added generated Memory Fast-Track guidance to `AGENTS.md`. Remember
validation passed with no errors or warnings.

### Key context

No application code exists yet. The documentation under `docs/` is the current
source of truth for implementation planning. The MVP targets the CIVA/Delco
Carousel IV-A and the iniBuilds L-1011's modeled Litton LTN-72 units for home
flight simulation only.

The delivery posture is a lean Vercel soft launch with Neon, Better Auth magic
links, Resend, a fail-closed email allowlist, production-only deployments, and
manual production migrations. Vitest runs in CI; a small Playwright suite is
manual for MVP.

### Decisions considered

- Chose typed domain commands plus a pure reducer and persisted snapshots over
  full event-sourced persistence.
- Chose Neon over a DigitalOcean database for the Vercel-hosted application.
- Chose Resend over SendGrid and Better Auth for database-backed magic links.
- Added optimistic concurrency and OFP-load idempotency at low engineering cost.
- Corrected the assumption that SimBrief Pilot IDs are always seven digits;
  they are variable-length numeric identifiers stored as strings.
- Deferred preview deployments, realtime synchronization, offline/PWA support,
  undo, reset, printing, and Playwright in CI.

### Blockers

No active blocker. Remaining implementation choices are explicitly listed in
`docs/planning-status.md`, including persistence shape, a defensive Pilot ID
length cap, the no-saved active-page fallback, optional SimBrief load throttling,
and test-environment mechanics.

## 19:40 Session

### What happened

Primed the repository and loaded its durable memory and existing daily journal.
Reviewed the planned implementation sequence, then confirmed that representative
OFPs can be retrieved from SimBrief's latest-OFP JSON endpoint using a numeric
Pilot ID.

Added `scripts/fetch_simbrief_ofp.py` as a dependency-free UV single-file
development tool. It validates a digits-only Pilot ID, fetches and validates the
latest JSON object, enforces a response-size limit, and atomically saves the raw
payload under `.local/simbrief/` with a UTC timestamp. Added the local output
directory to `.gitignore` and documented usage and privacy handling in
`README.md`.

Tested UV execution, CLI validation, a mocked successful fetch and atomic write,
malformed and oversized response rejection, Git ignore coverage, and diff
formatting. No live Pilot ID or real OFP was used during testing.

Recommended a focused SimBrief capture matrix: normal domestic, long multi-page,
oceanic, southern/eastern hemisphere, missing detailed navlog, and non-LIDO
OFPs, plus an optional sparse-metadata case. Consolidated those scenarios and
the implementation steps from `steps.md` into `docs/task-list.md`, then removed
the superseded `steps.md`.

### Key context

No web application code exists yet; the new Python file is a development data
acquisition tool. Raw OFPs may contain personal or account-related data and
remain ignored under `.local/simbrief/` until selected payloads are sanitized
into deterministic fixtures.

The SimBrief Pilot-ID endpoint returns only the latest generated OFP, so each
scenario must be fetched immediately after generation and associated with its
timestamped download. Exact page-boundary counts, coordinate rollover, malformed
numeric values, and similar rare cases should be derived synthetically rather
than forced through SimBrief.

### Decisions considered

- Used Python's standard library with UV PEP 723 metadata instead of adding an
  HTTP dependency.
- Chose a fixed ignored output directory and filenames that omit the Pilot ID.
- Preserved the original validated response bytes and used an atomic write to
  avoid partial files.
- Limited the real capture set to broad representative JSON shapes and reserved
  narrow parser edge cases for sanitized synthetic fixtures.
- Made `docs/task-list.md` the consolidated implementation checklist and removed
  the redundant root-level `steps.md`.

### Blockers

No active blocker. Representative OFPs have not yet been generated or captured.

### Next steps

   `docs/task-list.md`.
2. Record which timestamped download corresponds to each scenario.
3. Inspect the returned JSON and document exact field and waypoint

4. Sanitize representative payloads and derive deterministic synthetic edge
